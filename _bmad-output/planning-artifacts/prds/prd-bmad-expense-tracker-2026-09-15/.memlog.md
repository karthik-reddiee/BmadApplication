- (decision) Create a greenfield PRD for bmad-expense-tracker using finalized product brief as primary input and coaching path section-by-section per user request.
- (decision) PRD rigor calibrated as learning/internal: enough detail to drive architecture, epics, stories, sprint planning, and implementation; no launch-heavy market, compliance, risk, or measurement depth.
- (decision) Core product loop preserved as Record, Review, Understand, with fast manual expense entry as highest-priority interaction.
- (decision) MVP is a small single-user web app: expenses only, no real authentication required, defaults plus custom categories, mobile-friendly and approachable.
- (decision) MVP excludes advanced personal-finance scope including bank integrations, imports, investments, complex budgeting, bills, goals, forecasting, OCR, AI advice, and household sharing.
- (decision) Preferred technical direction is React, ASP.NET Core Web API, and PostgreSQL, but product requirements must remain capability-focused and leave architecture decisions to the architecture phase.
- (change) Added Document Purpose section explaining PRD audience, BMAD downstream use, capability-focus, and separation from architecture decisions.
- (decision) Vision is primarily user-facing: know where your money went without turning expense tracking into work; BMAD learning objective stays in project/document context, not value proposition.
- (change) Added Vision section with user product vision focused on fast manual tracking, Record-Review-Understand, and simplicity over full finance-platform breadth.
- (decision) Target user framed generally as an individual working professional with regular day-to-day expenses who wants better spending awareness without a complex personal-finance system; no named persona for MVP.
- (change) Added Target User section with general working-professional anchor, JTBD, and MVP non-user boundaries for prioritization and story framing.
- (decision) Use three lightweight key user journeys: immediate purchase recording, later recent-expense review/correction, and current-month spending understanding by total and category.
- (change) Added lightweight Key User Journeys UJ-1 through UJ-3 for immediate recording, recent review/correction, and current-month spending understanding.
- (decision) Glossary will use seven stable terms: Expense, Category, Default Category, Custom Category, Current Month, Recent Expenses, and Spending Summary.
- (change) Added Glossary with seven stable product terms and definitions to govern PRD vocabulary and future FR wording.
- (decision) MVP feature groups locked as Expense Recording, Expense Review and Maintenance, Category Management, and Current-Month Spending Summary; feature set stays limited to these unless needed for core experience.
- (change) Added Features scaffold with four MVP groups, product-loop mapping, descriptions, and placeholders for per-feature FR drafting.
- (decision) MVP uses one implicit application currency for amount display; currency is not an Expense field and multi-currency, conversion, exchange rates, and per-expense currency selection are out of scope.
- (change) Drafted Expense Recording FR-1 through FR-4 covering add Expense, default date, required-field validation, and under-30-second common entry path.
- (decision) Expense deletion requires a confirmation step before removal; cancel leaves Expense unchanged; MVP has no undo or recovery mechanism.
- (change) Drafted Expense Review and Maintenance FR-5 through FR-8 covering Recent Expenses list, Expense detail, edit, and confirmed delete without undo/recovery.
- (decision) Deleting a Custom Category is blocked when associated with existing Expenses; user must reassign those Expenses first; Default Categories remain protected from deletion.
- (change) Drafted Category Management FR-9 through FR-13 covering Default Categories, Custom Category create/edit/delete, deletion blocked when in use, and Default Category protection.
- (decision) Current-Month Spending Summary stands alone in MVP and answers where did my money go this month; previous-month comparisons, percentage changes, trends, and month-over-month analytics are future enhancements.
- (change) Drafted Current-Month Spending Summary FR-14 through FR-17 covering current-month total, category breakdown, current-month Recent Expenses, and summary updates after Expense changes.
- (decision) Include lean cross-cutting NFRs for usability, performance, data integrity, accessibility, and privacy/security; exclude enterprise availability, large-scale load testing, formal compliance, and production-grade security architecture.
- (change) Added lean Cross-Cutting NFRs for usability, performance, data integrity, accessibility, and privacy/security, plus explicit exclusions for enterprise-grade targets.
- (decision) Keep Non-Goals and MVP Scope separate: Non-Goals define broader product identity boundaries; MVP Scope defines concrete v1 implementation in/out boundaries.
- (change) Added separate Non-Goals and MVP Scope sections, including FR-mapped in-scope capabilities and explicit v1 out-of-scope list.
- (decision) Success Metrics remain product-focused: under-30-second entry, answer current-month total, answer category distribution; BMAD learning objective stays in Document Purpose/project context.
- (change) Added product-focused Success Metrics SM-1 through SM-3 and counter-metric SM-C1, excluding BMAD learning objective from metric section.
- (decision) Initial Default Categories are Food, Transport, Shopping, Bills, Entertainment, Health, Education, and Other; downstream UX/design may refine starter set for usability without expanding into complex category systems.
- (decision) MVP application currency is INR (₹), configured at application level and not user-selectable; multi-currency and conversion remain out of scope.
- (change) Resolved currency and Default Category open items in PRD; added Open Questions only for Recent Expenses count and all-Expense browsing UX.
- (change) Added Assumptions Index noting no unresolved inline ASSUMPTION tags and pointing remaining downstream design questions to Section 9.
- (change) Applied review/reconciliation fixes: explicit amount-first and prominent quick-add path, stable Recent Expenses ordering, category management role, lightweight NFR anchors, MVP trade-off paragraph, and stronger open-question timing/defaults.
